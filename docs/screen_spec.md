## 1. 目的

この文書は、VCL の画面ごとの役割、表示内容、操作、保存処理を整理するための画面仕様書である。

画面遷移は `frontend/src/main.js` と `frontend/src/router.js` で管理する。各画面は `frontend/src/views` 配下に配置する。

## 2. 共通仕様

### 2.1 画面構成

- SPA として動作し、History API により URL と表示画面を同期する。
- サイドバーから主要画面へ遷移できる。
- サイドバーには「ホーム」「クエスト」「フリー」「ログイン」「ひらめき」「トロフィー」を表示する。
- 画面本体は `#content-root` に描画する。
- ログイン、登録、404 などの補助画面も共通サイドバー配下で表示し、画面全体を覆ってサイドバーを隠さない。
- Joy-Con 入力はバックエンドの Socket.IO から `gyro-data` として受け取る。
- 画面HTMLは `template.html` や `*.template.html` に分離し、JSに長いHTML文字列を直書きしない。
- 動的なカードやセルはHTML側の `<template>` を複製し、JSではテキストや属性だけを差し込む。

### 2.2 保存先

| 情報 | 保存先 |
| --- | --- |
| 通常ユーザー情報 | LocalStorage の `vcl_user` / `vcl_token` |
| 学校運用の先生トークン | LocalStorage の `vcl_teacher_access_token` |
| 学校運用の生徒トークン | LocalStorage の `vcl_student_token` |
| ゲストまたは通信失敗時のトロフィー | LocalStorage の `vcl_user_trophies_offline` |
| 生徒ログインユーザーの進捗・トロフィー | Supabase |
| 通常ログインユーザーの進捗・トロフィー | 未実装。共同実装でDB方針を決める |

## 9. 実験室

| 項目 | 内容 |
| --- | --- |
| 目的 | 3D 空間で実験操作を行う |
| データ | `quests.js`、周期表データ、Socket.IO の Joy-Con 入力 |
| 主な表示 | 試験管、フラスコ、液体、固体、ツールバー、ミッション文 |
| 主な操作 | 薬品選択、注ぐ、振る、混ぜる、周期表選択 |
| 成功時 | 解説ダイアログ表示、進捗保存、トロフィー保存 |

### 9.1 セレクト実験

- `params.id` の実験 ID をもとに `quests.js` からクエストを取得する。
- `mission` を実験中の指示として表示する。
- `toolbarActions` から薬品投入ボタンを生成する。
- `reaction` の条件を満たしたら成功扱いにする。

### 9.2 フリーモード

- `/free-mode` から入った場合は、タイトルを「フリー実験」とする。
- サイドバーの「フリー」から `/free-mode` へ遷移できる。
- 周期表は118元素を表示し、任意の元素を試験管またはフラスコへ設定できる。
- 周期表の閉じるボタンは右上に表示し、左上の水素などの元素セルとクリック領域が重ならないようにする。
- 周期表で元素セルをクリック、またはJoy-ConのAボタンで選択した場合、周期表を閉じて薬品セット先選択モーダルを表示する。
- フリーモードでは、試験管とフラスコに現在入っている物質名を左上のステータス領域に表示する。
- ステータス領域には、未設定、注入待ち、混合中、反応判定中、観察結果表示済みの状態と、混合進行度バーを表示する。
- ステータス領域には、周期表118元素×118元素の13,924通り対応、全件データ13,924件、検証分類13,924件、生成物確定1,168通り/584組、seed件数を表示する。
- 注いで混ぜた後、フリーモード反応APIへ組み合わせを送信し、DB登録済み反応またはAI補完キャッシュの観察結果を表示する。
- APIが低信頼の `unknown` または目立つ変化なし相当の結果を返した場合、DB確定結果でない限りローカル周期表推定の観察結果を優先して表示する。
- 反応APIの `visualDetail` を3D表示に反映し、結晶、粉状沈殿、薄片、気体の泡、溶解粒子、液体色変化、目立つ変化なしを分けて表示する。
- APIが生成物名、固体形状、固体色、気体名、泡色、必要条件を返した場合は、観察テキストだけでなくフラスコ内の生成物表現にも利用する。
- API が利用できない場合、またはAPIが低信頼のフォールバック結果を返した場合は、フロントエンド内の `freeModePeriodicReactionData.json`、`freeModeReactionSeed.json`、学校実験向け簡易ルールで観察結果を代替表示する。
- 周期表元素どうしの組み合わせは `freeModePeriodicReactionData.json` の順序付き全件データを優先し、試験管側とフラスコ側の順番を表す `H->O` 形式のキーで参照する。
- 科学的に生成物を断定できる代表反応のみ、生成物名、反応式、泡・沈殿・結晶・色変化などの演出を表示する。
- 条件依存の元素ペアは、観察文で「条件依存（生成物は断定しない）」と示し、生成物や反応演出を断定しない。
- 周期表の詳細データが未登録の元素でも、英語名、分類、外観の最低限の情報を表示する。
- 成功判定やトロフィー付与は、クエスト指定がある場合を優先する。

### 9.3 保存処理

| タイミング | 保存内容 | 保存先 |
| --- | --- | --- |
| 実験成功 | `completed` 進捗 | 生徒ログイン時は `/api/school/students/progress` |
| 実験成功 | トロフィー ID | 生徒ログイン時は `/api/school/students/trophies` |
| 通常ログイン時 | 進捗・トロフィー | 未実装。共同実装でDB方針を決める |
| 通信失敗 | トロフィー ID | LocalStorage |
